# 키워드 검색량 — 안드로이드 앱

네이버 키워드 월간 검색수, 연관 키워드, 블로그 포화도, 트렌드를 휴대폰에서 바로 보는 앱입니다.
**사용자마다 자기 네이버 API 키를 넣어 쓰는 방식**이라 서버가 없고, 키와 조회 기록은 각자 휴대폰 안에만 저장됩니다.

## 들어있는 것

| 경로 | 내용 |
|---|---|
| `www/` | 앱 화면과 조회 로직 (서명, 매칭·재확인, 포화도, 트렌드, 기록, 엑셀) |
| `android/` | 안드로이드 프로젝트 (아이콘, 백업 차단, 서명 설정 포함) |
| `.github/workflows/build-apk.yml` | GitHub 자동 빌드 → 릴리스에 APK 게시 |
| `build_apk.bat` | 내 PC에서 APK 만들기 |
| `tools/QR_만들기.html` | 다운로드 링크로 QR코드와 A4 현장 안내문 만들기 |
| `signing/` | 내 PC 빌드용 서명 키를 넣는 자리 (GitHub에 올리지 않음) |

서명 키는 **별도 압축 파일(서명키_보관용)** 로 드렸습니다. 이 프로젝트 폴더와 섞지 마세요.

---

## 배포 흐름 한눈에

```
[처음 한 번]  GitHub 저장소 만들기 → 파일 올리기 → 서명 키 Secrets 등록
[빌드]        Actions → "APK 빌드" → Run workflow (버전 1.0.0) → 5~10분
[현장]        고정 다운로드 링크 → QR_만들기.html → A4 인쇄해서 부착
[업데이트]    코드 수정 → Run workflow (버전 1.0.1) → QR 그대로, 앱이 새 버전 알림
```

---

## 방법 A. GitHub 자동 빌드 (추천 · PC에 설치할 것 없음)

### 1) 저장소 만들기
1. https://github.com 가입 · 로그인
2. 오른쪽 위 **+ → New repository**
3. 이름: `keyword-app` (아무거나), **Public** 선택 → **Create repository**
   - Public이어야 QR로 누구나 로그인 없이 APK를 받을 수 있습니다. 코드는 공개되지만 API 키·서명 키는 들어있지 않습니다.

### 2) 파일 올리기
1. 새 저장소 화면의 **uploading an existing file** 클릭
2. 압축을 푼 `keyword-app` 폴더 **안의 내용 전부**를 끌어다 놓기 (`signing` 폴더는 빼도 되고, 안에 README만 있으면 올라가도 무방)
3. 아래 **Commit changes**
4. 저장소 첫 화면에 `.github` 폴더가 보이는지 확인합니다.
   - 안 보이면: **Add file → Create new file** → 파일 이름에 `.github/workflows/build-apk.yml` 입력 → 이 프로젝트의 같은 파일 내용을 그대로 붙여넣고 Commit

### 3) 서명 키 등록 (처음 한 번)
1. 저장소 **Settings → Secrets and variables → Actions → New repository secret**
2. `서명키_보관용/GitHub_Secrets_붙여넣기.txt` 를 열어 4개를 이름 그대로 등록
   `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`

### 4) 빌드
1. 저장소 **Actions** 탭 → (처음이면 *I understand… enable* 클릭) → 왼쪽 **APK 빌드**
2. **Run workflow** → 버전 `1.0.0` → 초록 버튼
3. 5~10분 뒤 초록 체크가 뜨면 완료. 오른쪽 **Releases** 에 APK가 올라갑니다.

### 5) 고정 다운로드 링크 (QR에 넣을 주소)
```
https://github.com/<내아이디>/<저장소이름>/releases/latest/download/keyword-volume.apk
```
새 버전을 빌드해도 이 링크는 항상 최신 APK를 가리킵니다. **QR을 다시 만들 필요가 없습니다.**
앱도 켤 때 이 저장소의 `version.json`을 확인해서 새 버전이 있으면 "받기" 안내를 띄웁니다.

## 방법 B. 내 PC에서 빌드

1. **Node.js LTS** 설치: https://nodejs.org/ko
2. **Android Studio** 설치: https://developer.android.com/studio → 한 번 실행해 기본(Standard) 설치 완료
3. `서명키_보관용`의 `keyword-release.jks`, `keystore.properties` 를 이 폴더의 `signing\` 에 복사
4. `build_apk.bat` 더블클릭 → 버전 입력 (처음 1.0.0) → 처음엔 10분 안팎
5. `결과물\keyword-volume.apk` 생성
6. 이 파일을 구글 드라이브 등에 올리고 **링크가 있는 모든 사용자** 공유 링크를 QR로 만듭니다.
   - 이 방식은 링크가 버전마다 바뀔 수 있어 새 버전 알림이 동작하지 않습니다. 알림을 쓰려면 `update_url.txt` 에 version.json 주소를 한 줄로 넣고 빌드하세요.

## 현장 QR 안내문 만들기
1. `tools/QR_만들기.html` 을 크롬으로 열기 (인터넷 없어도 됨)
2. 다운로드 링크 붙여넣기 → **QR 만들기**
3. **인쇄 / PDF 저장** (A4 한 장: QR + 설치 3단계 안내) 또는 **QR 이미지(PNG) 저장**
4. 붙이기 전에 내 휴대폰으로 한 번 찍어서 다운로드·설치까지 되는지 확인하세요.

---

## 업데이트 배포
1. 수정한 파일을 저장소에 다시 올리기 (같은 이름 파일은 덮어쓰기)
2. Actions → APK 빌드 → **이전보다 큰 버전** (1.0.0 → 1.0.1)
3. 사용자는 앱을 켜면 "새 버전이 있습니다 → 받기"가 뜨고, 받아서 설치하면 **기록과 키가 그대로 유지**됩니다.

## 서명 키 보관 (중요)
- 업데이트 APK를 기존 앱 위에 설치하려면 **항상 같은 서명 키**로 빌드해야 합니다.
- `서명키_보관용` 압축 파일은 USB나 개인 클라우드에 따로 보관하세요. 잃어버리면 사용자들이 앱을 지우고 다시 설치해야 합니다(기록 사라짐).
- 서명 키 파일을 공개 저장소에 올리거나 남에게 보내지 마세요.

## 첫 실기기 확인 목록
- [ ] QR → 다운로드 → 설치 → 실행
- [ ] 첫 화면 키 입력 → **연결 확인** 성공
- [ ] `전주맛집` 빠른 조회 → 검색수가 키워드도구 값과 비슷한지
- [ ] 카드 누르기(펼침), 길게 누르기(선택) → 트렌드 비교
- [ ] 엑셀 공유 → 카카오톡/드라이브로 보내지는지
- [ ] 뒤로가기 버튼 동작, 앱 다시 켰을 때 기록 남아있는지

## 문제 해결
| 증상 | 해결 |
|---|---|
| Actions 빌드가 "서명 키 Secrets가 없습니다"로 실패 | 3) 서명 키 등록의 4개 이름·값 확인 |
| Actions 탭에 "APK 빌드"가 없음 | `.github/workflows/build-apk.yml` 이 저장소에 없음 → 2)-4 참고 |
| QR로 받으면 404 | 저장소가 Private이거나 아직 빌드 전. Public 확인, Releases에 파일 있는지 확인 |
| "앱이 설치되지 않음" (업데이트 시) | 다른 서명 키로 빌드됨. 항상 같은 Secrets 사용 |
| 설치 시 Play 프로텍트 경고 | 스토어 밖 앱이라 뜨는 안내. 세부정보 → 무시하고 설치 |
| 연결 확인이 '인증 실패' | 키 앞뒤 공백·일부 복사. 비밀키는 '보기' 후 전체 복사 |
| 검색수가 이상함 | 앱 [설정 → 검색량 진단]으로 원본 응답 확인 → 진단 결과 복사해서 문의 |
| 일괄 조회 중 멈춤 | 앱을 내리면 휴대폰이 앱을 멈춥니다. 화면을 켠 채로 기다리세요 |

## 데이터와 보안
- API 키·기록은 앱 전용 저장공간에 저장됩니다(다른 앱 접근 불가). 휴대폰 백업·기기 이전으로도 빠져나가지 않게 막아 두었습니다. 별도 암호화는 하지 않습니다.
- 앱은 네이버 API(api.searchad.naver.com, openapi.naver.com)와, 설정된 경우 업데이트 확인 주소 외에는 통신하지 않습니다.
- 사용자가 [설정 → 백업]에서 "API 키도 함께 백업"을 켠 경우에만 백업 파일에 키가 들어갑니다.

## 제약
- 안드로이드 7.0 이상 전용입니다. 아이폰은 설치할 수 없습니다.
- 개발자센터 키(블로그·데이터랩)는 사용자마다 하루 호출 한도가 있습니다.
- 나중에 구글플레이에 올리려면 같은 프로젝트에서 `bundleRelease`(AAB)로 빌드하면 됩니다.
